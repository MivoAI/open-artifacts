Instance runtime · minimum architecture

Package 创建 Instance，Instance 独立持久

OA Daemon 管理 Artifact Instance 的身份、Package Binding 和三态生命周期，并围绕每个 Instance 提供 Data、Annotation 与 Tool。Artifact Runtime 可以停止或换用新的 Package， Instance ID、工作内容和标注不会因此消失。

01 一个持久化身份Package 是定义；Instance 才是用户正在工作的对象。
02 三项核心能力Data 保存内容，Annotation 保存上下文，Tool 执行领域操作。
03 三个生命周期状态只有 Active、Stopped、Archived；其余都是操作。

One durable object

人和 Agent 通过不同入口，共同作用于一个 Instance

Human 通过 Artifact UI 与 Annotation UI 协作；Package Runtime 使用自动绑定当前 Instance 的 OA SDK，外部 Agent 使用显式 instanceId 的 OA CLI / Remote MCP Adapter。 两条路径最终进入同一个 OA Daemon。

Definition ≠ object ≠ process ≠ surface

四个术语各自只回答一个问题

Package、Instance、Runtime 与 UI 不再互相代称。尤其是 Instance 是持久化对象， Runtime 只是它在 Active 状态下使用的短生命周期执行环境。

What can be instantiated?

Artifact Package

可复用定义。一个 Package 可以创建多个拥有不同 Data 与 Annotation 的 Instance。

package + input → instance
What is the user working on?

Artifact Instance

持久化工作实体。它拥有稳定 ID，并跨生命周期与 Package Binding 替换保持同一身份。

identity + binding + data + annotation
What is running now?

Artifact Runtime

只在 Active 时存在。停止或换用新的 Package Runtime，不会删除 Instance 及其持久数据。

start / stop
What does the human see?

Artifact UI

由 Package 定义、从 Instance Data 呈现出的交互界面，不承担持久化身份。

data → visible interface

Three states only

生命周期只有 Active、Stopped、Archived

Create、Start、Stop、Archive 与 Restore 都是操作，不是状态。新建 Instance 默认进入 Stopped；Archived 必须先 Restore 为 Stopped，才能再次 Start。

State

Active

Artifact Runtime 正在提供 UI 与 Package Tools；Data 和 Annotation 接口同时可用。

runtime: running
stop → ← start
State

Stopped

Runtime 不运行；Instance ID、Data、Bindings 与 Annotations 完整保留。

runtime: absent
archive → ← restore
State

Archived

Instance 已归档并保留恢复所需内容；恢复前不能启动 Runtime 或调用 Tool。

restorable: true

Archive 只从 Stopped 进入。这样每次归档都面对一个已停止、边界稳定的 Instance； 删除归档不是第四个状态，而是另一个管理操作。replacePackage 也不是新状态： Daemon 停止旧 Runtime、替换 Package Binding，再用新 Package 启动同一个 Instance。

Two API forms · Three capabilities

两种 API 形式，访问同三项 Instance 能力

OA SDK 只注入 Artifact Runtime，并隐式绑定当前 Instance；OA CLI 面向外部 Agent 与本地自动化，所有请求显式传 instanceId。Remote MCP 只是 External Agent Interface 的另一个 Adapter，不形成第三套语义。

Programmatic API OA SDK

Package UI 与 Tool Handler 使用。Runtime Context 自动限定当前 Instance，因此 Package 调用 Data 与 Annotation API 时不传 instanceId。

Command-line API OA CLI

外部 Agent 使用参数、stdin/stdout、文件路径与退出码访问 Instance；每次调用显式传 instanceId。Remote MCP 映射同一个 External Agent Interface。

Runtime synchronization contract SDK State / Data Binding

开箱即用地提供当前 snapshot、mutation 与 revision 变化后的重新获取 / 订阅，让 Artifact UI 收敛到权威 Data。具体采用 event stream、polling、signals、React context 或其他机制，此阶段不做工程选型。

Runtime SDK（implicit Instance）/ Agent Adapter（explicit instanceId）→ OA Daemon → 幂等校验 → Git revision → receipt + change event
Persistent content

Data API

SDK 与 CLI 的参数纪律不同；Data 的 Contract 校验、幂等、Git revision、receipt 与 change event 都由 Daemon 保持唯一。

  • SDK data.bind → binding.read / update current Instance
  • CLI data read / write explicit instanceId
Human context

Annotation API

保存人的表达、Target 与 Snapshot；每次 mutation 返回 annotationId、revision、 status，并产生 Annotation change event。

  • annotation.list 读取线程
  • annotation.create 提交标注
  • annotation.reply 回复上下文
  • annotation.resolve 基于最新 revision
Package operations

Tool API

列出当前 Package 的 Tool 定义，并把调用绑定到一个具体 Artifact Instance。

  • tool.list(instanceId) 发现能力与状态
  • tool.call(instanceId, …) 幂等调用 Handler

Concrete local-first storage

Instance Bundle 默认由 OA 托管，也可以迁入用户工程

OA 默认在自己的 Home 中创建并托管一个 name.openartifact/。迁移保持 Instance ID、Data revision、Annotations 与 Package Binding，不创建新 Instance；新位置成为唯一权威 Bundle，OA Home 只记录当前位置关联，不保留影子副本。Bundle 内只保存 Instance 真正拥有的内容；大型原始视频、用户现有 Markdown 或线上数据源可以继续留在外部，由 Data Binding 保存关系和访问方式。参见 ADR-0001。

Minimum core

核心只实现一个 Daemon、一个管理器和三项能力

这次收敛不是删除必要行为，而是不把每项内部责任提前画成独立模块。出现真实变化需求后， 再从已有接口内部提取新的实现接缝。

Build now

当前核心

一个 OA Daemon，内部只有 Instance Manager 与 Data、Annotation、Tool 三项能力。

  • Instance Manager：身份、三态生命周期与同一 Instance 的 Package replacement。
  • Data：Data API、Managed Data、外部 Bindings、幂等与 Git revision。
  • Annotation：Target resolution、Snapshot、receipt / event 与状态。
  • Tool：Package 定义、list、call、Active 检查与 Handler 路由。
  • Runtime SDK Context：自动绑定当前 Instance，并提供 State / Data Binding。
Do not split yet

不作为一级模块

这些行为可以存在于核心实现内部，或者等到出现两个真实实现后再提取。

  • Gateway / Policy Gate：先作为 OA Daemon 的入口检查。
  • Commit Coordinator：不拆成服务；幂等、原子写入与 receipt 是 Daemon 内部实现。
  • State Observer：SDK Binding 是稳定接口，event stream / polling 等机制暂不决策。
  • Task Manager / Audit Recorder：当前闭环不依赖，暂不进入核心。
  • Public State：不再作为独立概念，持久工作内容统一称为 Data。
  • Remote Source Access：云端 Agent 暂不能 fork / 编辑本地 Package，等待统一文件系统抽象。
