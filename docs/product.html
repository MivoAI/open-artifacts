Product model

用泳道时序图看清角色怎么协作

外部角色只有 Human 与 Agent。OA 的核心是常驻的 OA Daemon，管理所有 Artifact 的生命周期与持久化；OA Interface（CLI / Remote MCP）、SDK、OA Workbench 只是入口，Package 提供 UI 与 Tool，Instance 保存 Data 与 Annotation。下面按八组、十一条场景路径看消息怎么走。

① Human 人：验收与直接操作
② OA Workbench · SDK · OA Interface（CLI / Remote MCP）· Daemon
③ Artifact Package · Artifact UI · Data · Annotation（同色、相邻）
④ Agent 外部智能体：经 OA Interface（本地 CLI 或云端 Remote MCP）进入

Roles

谁在泳道里

泳道按 scope 相邻排列：Human → OA（Workbench / SDK / Interface / Daemon）→ Artifact（Package / UI / Data / Annotation）→ Agent。Agent 入口假定有两种调用形式：本地 OA CLI 与云端 OA Remote MCP，都转发到同一 Daemon。

External

Human

指出问题、直接改内容、验收结果。只碰 Artifact UI 与 OA Workbench。

External

Agent

运行时交互经 OA Interface（本地 CLI 或云端 Remote MCP）。默认调 Tool；能力不足时直读写 Data。本地 Agent 还可以修改新的 Package，再让同一个 Instance 切换 Package Binding。

Platform

OA

核心是常驻的 OA Daemon：管理所有 Artifact 的生命周期，持有 Data Authority 与 Annotation Store，路由 Tool 调用；Workbench / SDK / OA Interface（CLI · Remote MCP）都是它的入口。不解释业务。

Boundaries

读图时钉死的边界

箭头方向比模块名更重要。

OA Daemon 是中枢 OA Interface（CLI / Remote MCP）、SDK、OA Workbench 只是入口；生命周期、Data Authority、Annotation Store 都在 Daemon。
Agent 两种调用形式 本地 Agent 走 OA CLI；云端 Agent 走 OA Remote MCP，可操作远端 OA 内容。二者都是转发适配器，语义相同，最终汇到同一 Daemon。图中 OA Interface 泳道代表这两种形式。
两条写 Data 的路，同一个权威提交 Artifact UI / Tool Handler 经注入的 OA SDK 写当前 Instance，不传 instanceId； Agent 默认经 Tool，能力不足才经 OA Interface 的 Data API，并显式指定 instanceId。 两者最终都由 Daemon 校验与提交。
两条读 Data 的路 场景 1 用 timeline.inspect 获得 Package 定义的领域视图；场景 2 在 Tool 能力不足时经 Data API 读取原始 Data。两者都由 Daemon 访问权威 Data，并经 OA Interface 返回 Agent。
SDK Binding 让 UI 收敛，不整页刷新 每次成功提交都产生新的 Instance revision 与 change event。OA SDK 提供开箱即用的状态 / 数据绑定，让 Artifact UI 按 revision 重读或更新投影； 具体使用事件流、轮询还是前端状态库留到工程设计阶段。
Annotation 不是执行 所有 Annotation 写操作都返回 {annotationId, revision, status} 并产生 change event。执行前必须在当前 Data 上 resolveTarget；Tool 成功先记录证据并标为 applied，验证通过或 Human 验收后才 resolved，失败保持 open。
场景 1 展示一次通用前置检查 Agent 首次调用先检查 Instance 状态并 tools.list；可能返回 TOOL_NOT_FOUND、 INPUT_INVALID、INSTANCE_STOPPED、INSTANCE_ARCHIVED 或 Handler 失败。后续场景默认 已完成相同检查，不重复画出。
Daemon 管幂等，Git 记录 revision Agent mutation 携带 baseRevision 与 idempotencyKey；Daemon 保证重复请求只生效一次， 并把成功的 Data 提交记录为 Git revision。SDK 调用由 Runtime 限定当前 Instance， 不要求 Package 传 instanceId。
改 Data ≠ 换 Package 场景 0、2B、3、4、5、6A 改的是 Instance Data；场景 7 保留同一个 instanceId、Data 与 Annotations，只替换 Package Binding 并启动新的 Runtime。云端 Agent 暂时不能访问本地 Package 源码，这是等待统一文件系统抽象解决的已知限制。
